# 검증 가능한 인계와 역할 — 승인된 구현 범위

사용자가 역할/인계 QA 결과를 바탕으로 전체 구현과 가능한 모델/에이전트 QA를 요청했다.

1. 역할 5종의 기본 모델/effort를 유지하고 읽기 전용 역할의 테스트 실행 지시 충돌을 해소한다. 최종 검증/수락/담당 이전은 코디네이터의 책임이다.
2. Worker 실행 종료와 작업 결과를 분리한다. 결과는 ready/blocked/failed/changes_requested/accepted이며 accepted는 코디네이터가 근거와 독립 검토를 확인한 후에만 기록한다.
3. Python 표준 라이브러리 SQLite로 저장소 밖 로컬 상태를 보관한다. task, attempt, checkpoint, session-transfer, receipt, commit을 명시한다. 담당자와 버전은 원자적으로 확인/변경한다.
4. 인계 준비만으로 담당자를 바꾸지 않는다. 수신 시 Git HEAD·미커밋 내용·근거 파일·기존 실행 여부를 재확인한다. 실행 중/미확인 attempt, 변경된 snapshot, 중복 인수, 잘못된 담당자는 거부한다. 인수 확정 전에도 재확인한다. 임의의 Claude 실행까지 강제로 막는 보안 경계라고 주장하지 않는다.
5. CLI와 han-resume 스킬을 제공한다. handoff는 요약 문서와 한 줄 재개 안내를 로컬에 만든다. 설치 파일과 런타임도 함께 설치하며 기존 파일 충돌/백업 보호를 유지한다. 웹은 읽기 전용을 유지한다.
6. 시각화에 role 배지, 실행 종료와 결과 상태, 결과 수신함, 인계 준비/수신/확정 타임라인, 이전 담당 기록을 표현한다. 이벤트 없는 세션 간 관계는 추측하지 않는다. 데모 role 오류를 수정하고 가상 인계 예제를 제공한다.
7. 합성 실패/중복/변경/세션 종료/재시작, 실제 Git fixture, 다중 프로세스 동시 인수, UI/모바일/키보드/동작 줄이기와 가능한 실제 Claude role/model 호출을 검증한다. 실제 모델 호출의 실패/미실행은 숨기지 않는다.
8. 개인 대화·경로·실제 모델 응답 원문은 공개 Git에 포함하지 않는다. 공개 QA 보고서는 익명화된 집계와 재현법만 포함한다.

접근법: 문장 추측만으로 연결하면 인계 수신을 증명하지 못한다. hooks 전체 설치는 이번 목적에 필수가 아니므로, 명시적 CLI 이벤트 + 기존 transcript의 읽기 전용 관측을 조합한다. 별도 handoff LLM은 추가하지 않는다.
